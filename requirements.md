3. [architect] Write `engine/src/ipc/protocol.h`: struct `RecvBuffer { char chunk[4096]; std::string accumulated; }` — owned by Session, passed by reference to all recv calls so partial reads carry over between messages and across phase transitions; functions `send_json(fd, json)` (newline-terminated), `recv_json(fd, RecvBuffer&)` (buffered read, max 64KB, timeout 15s), `read_exact(fd, buf, n, timeout_ms)` (internal: loops poll+read until n bytes received or error), `recv_binary_frame(fd, RecvBuffer&)` (drains `RecvBuffer.accumulated` first — **including partial header bytes** already over-read during the JSON phase — before touching the fd; 4-byte big-endian length prefix; zero-length = sentinel), `send_error(fd, code, message)`; error codes enum: `malformed_json`, `phase_violation`, `corrupt_audio`, `inference_failed`, `session_limit`, `timeout`, `duration_exceeded`; add `send_warning(fd, code, message)` alongside `send_error` — warning does NOT reset session state, engine continues after sending it; warning code: `approaching_context_limit` (sent when recording hits 80% of ctx_size budget)

4. [devops] Write `engine/src/ipc/protocol.cpp`: `send_json()` serializes nlohmann::json + `\n`, writes to fd; `recv_json(fd, buf)` — buffered read: poll() once with timeout → read() up to 4096 bytes into buf.chunk → append to buf.accumulated → scan for `\n`; on find: extract message, leave remainder in buf.accumulated; on accumulated > 64KB without `\n`: throw `"json message too large"`; on poll timeout: throw `"timeout"`; `read_exact(fd, buf, n, timeout_ms)` — loops poll()+read() until exactly n bytes received or error; throws `ConnectionClosed` on EOF, `"timeout"` on deadline; never returns partial; `recv_binary_frame(fd, buf)` — **explicitly drain partial header bytes from buf.accumulated first**: `size_t already_have = std::min(buf.accumulated.size(), size_t{4}); memcpy(header_buf, buf.accumulated.data(), already_have); buf.accumulated.erase(0, already_have); read_exact(fd, header_buf + already_have, 4 - already_have, timeout_ms)` → decode big-endian length → if 0 return empty (sentinel) → `read_exact()` for payload → return `vector<uint8_t>`; on EPIPE/ECONNRESET throw `ConnectionClosed`

[architect] Write `engine/src/ipc/session.h`: class `Session` with states enum `{IDLE, WAITING_READY, STREAMING_AUDIO, INFERRING, SHUTDOWN, DESTROYED}`; `handle_connection(fd, Engine&)` drives the full session lifecycle on the calling thread; **`stop()`** sets `stop_inference_thread_ = true`, `abort_inference_ = true`, notifies `infer_cv_`, joins `inference_thread_` — safe to call multiple times (idempotent via `std::call_once` or flag check); **destructor calls `stop()`** as a safety net; owns: `RingBuffer ring_buffer_` (SPSC: session thread = producer, inference thread = consumer), `std::thread inference_thread_` (started at Session construction; loop: wait on `infer_cv_` → if `stop_inference_thread_` break → infer → write result → notify `result_cv_` → loop), `std::atomic<bool> abort_inference_{false}`, `std::atomic<bool> stop_inference_thread_{false}`, `ProgressQueue progress_queue_`, `std::optional<InferenceResult> inference_result_` (guarded by `std::mutex result_mutex_`)

7. [devops] Write `engine/src/ipc/session.cpp`: implements state machine — **IDLE**: receives `session.start` → WAITING_READY; `ping` → send `pong`, stay IDLE; `session.shutdown` → SHUTDOWN; 15s idle timeout → close connection; **WAITING_READY**: `engine.ensure_loaded()` (may block ~4s; `g_interrupted` not checked during load — SIGINT deferred up to ~4s until control returns to poll loop) → send `session.ready` → STREAMING_AUDIO; load error → error JSON → IDLE; 30s load timeout → IDLE; **STREAMING_AUDIO (file-based)** — binary-only phase, client sends no JSON: reads frames via `recv_binary_frame`; update `last_frame_time_` per frame; timeout checks before each read: (a) no-first-frame 15s → timeout → IDLE; (b) mid-stream stall 30s → timeout → IDLE; (c) duration ≥ 5 min → `duration_exceeded` → IDLE; **ctx overflow check every 30s boundary**: `max_audio_secs = (ctx_size - SYSTEM_PROMPT_TOKENS_RESERVED) / AUDIO_TOKENS_PER_SEC`; if `ring_buffer_.duration_secs() >= max_audio_secs * 0.8` → `send_warning(fd, "approaching_context_limit", ...)` (session continues); if `ring_buffer_.duration_secs() >= max_audio_secs` → send `duration_exceeded` error → IDLE (prevents silent truncation); zero-length sentinel → **VAD-to-zero check**: if `ring_buffer_.bytes_available() == 0` after sentinel → skip inference, send `{"type":"result","text":"","command":null}` → IDLE; otherwise set `infer_ready_ = true`, notify `infer_cv_` → INFERRING; EOF/EPIPE → IDLE; **STREAMING_AUDIO (mic-based)**: start `AudioCapture`; session thread polls socket 100ms for `{"type":"session.end"}` JSON (JSON phase resumes from client side); duration check per iteration; `session.end` or limit → `AudioCapture.stop()` → notify `infer_cv_` → INFERRING; **INFERRING** — Phase 3, JSON phase: session thread polls socket: `poll(socket_fd, POLLIN, 100ms)` → if POLLIN → `recv_json()` → if `session.start` → `abort_inference_ = true` → wait `result_cv_` → **`ring_buffer_.reset()`** → WAITING_READY (reuse); if `session.shutdown` → `abort_inference_ = true` → SHUTDOWN → `stop()` → DESTROYED; EOF → `abort_inference_ = true` → `ring_buffer_.reset()` → IDLE; on poll timeout: drain `progress_queue_`, send `progress` JSONs; on `inference_result_` ready → send `result` JSON → clear `abort_inference_` → **`ring_buffer_.reset()`** → IDLE; 30s inference timeout → `abort_inference_ = true` → timeout error → `ring_buffer_.reset()` → IDLE; **SHUTDOWN** → `stop()` → DESTROYED; **inference thread loop (Session lifetime)**: `unique_lock; infer_cv_.wait(lk, [&]{ return infer_ready_ || stop_inference_thread_; })` → if `stop_inference_thread_` break → `ring_buffer_.read_all()` → `engine.process_stream(pcm, context, abort_inference_, progress_queue_)` → write `inference_result_` + notify `result_cv_` → reset `infer_ready_` → loop; **abort frequency**: `process_stream()` (and the backend implementation) MUST check `abort_flag` at minimum every 32 generated tokens — if `abort_flag` is checked only at coarse boundaries, `result_cv_.wait()` in the session thread can hang for seconds on long batches; 32-token interval ≈ 0.5–1s max wait on M3 Pro
