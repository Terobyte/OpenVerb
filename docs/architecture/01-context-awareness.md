# Механизмы определения контекста (Context Awareness)

## Значение контекста в системе

**Определение**: Context Awareness — способность системы понимать:
- В каком приложении находится пользователь
- Какой документ открыт
- Какое поле ввода активно
- Какой текст выделен
- Что находится в буфере обмена

**Без контекста**: система генерирует сухой, неструктурированный текст, требующий ручного редактирования.

**С контекстом**: AI автоматически адаптирует стиль, форматирование и семантику.

## Иерархия контекстных данных

### 1. Application Context (Контекст приложения)

**Что извлекается:**
- Название активного процесса
- Заголовок окна
- Текст из текущих полей ввода

**Пример использования:**
- **Slack**: неформальный стиль, эмодзи, краткость
- **Email**: формальный тон, правильная пунктуация
- **VS Code**: camelCase/snake_case, JSDoc-комментарии, правильные отступы

### 2. Selected Text Context (Контекст выделенного текста)

**Использование**: преобразование существующего текста, а не создание нового.

**Команды вида:**
- «Перепиши этот абзац более убедительно»
- «Исправь логическую ошибку в этой функции»
- «Превратить в маркированный список»

**Логика**: выделенный текст становится объектом для команд редактирования.

### 3. Clipboard Context (Контекст буфера обмена)

**Использование**: многоходовые рабочие процессы.

**Пример сценария:**
1. Разработчик копирует stack trace из логов сервера
2. Переключается в окно мессенджера
3. Активирует голосовой ввод
4. Говорит: «Сформируй тикет на основе этой ошибки»
5. AI невидимо извлекает ошибку из буфера и генерирует структурированный текст

**Механизм**: "невидимый скрытый буфер" кэширует данные между сеансами диктовки.

## Структурирование контекстных данных

Продвинутые системы классифицируют контекст в структурированные категории, которые затем передаются LLM.

### Архитектура Superwhisper

```json
{
  "applicationContext": {
    "processName": "VS Code",
    "windowTitle": "index.ts",
    "activeFieldContent": "function calculateMetrics(data) {\n  // user's cursor position\n}",
    "language": "typescript"
  },
  "selectedTextContext": {
    "text": "const result = doSomething(x, y, z);",
    "isActive": true
  },
  "clipboardContext": {
    "text": "Error: Maximum call stack size exceeded",
    "captureTime": "2024-04-13T09:15:00Z",
    "isActive": false
  }
}
```

## Механизм невидимого кэша

**Сценарий**: пользователь прерывает диктовку нажатием Escape.

**Что происходит:**
1. Собранные контекстные данные временно кэшируются
2. Выделенный текст и буфер остаются доступны
3. Сторонние скрипты могут обращаться к кэшу
4. Позволяет повторную обработку без перевыделения

**Преимущество**: ускорение итеративных команд редактирования.

## Примеры адаптации к контексту

### Одна и та же фраза в разных окнах

**Фраза**: "let's meet tomorrow — actually let's do Friday instead"

| Приложение | Адаптация | Результат |
|-----------|-----------|----------|
| **Slack** | Неформальный, удаление самокоррекции | «Let's meet Friday!» |
| **Email** | Формальный, полные предложения | «I propose we reschedule our meeting to Friday instead.» |
| **Calendar** | Структурированная команда | Создание события на Friday |
| **Notes** | Сохранение исходной интонации | Полный текст как диктовка |

### Code-специфичный контекст

**Выделенный код:**
```python
def process_data(items):
    for item in items:
        print(item)
```

**Голосовая команда**: "add error handling"

**AI понимает из контекста:**
- Язык: Python
- Стиль: существующий в файле
- Отступы: 4 spaces
- Возвращаемые типы: нужны ли

**Результат:**
```python
def process_data(items):
    try:
        for item in items:
            print(item)
    except Exception as e:
        logger.error(f"Error processing item: {e}")
        raise
```
